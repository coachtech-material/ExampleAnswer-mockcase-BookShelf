# 書籍レビューアプリ 要件定義書・基本設計書（応用機能編 - 詳細度50%）

## 1. はじめに

### 1.1. 本書の目的と進め方

本書は、書籍レビューアプリケーションの「応用機能編」開発における主要な要件と設計の概要を定義するものです。実際の開発現場では、最初から完璧な仕様書が渡されることは稀です。多くの場合、大まかな要件を元に、開発者は自ら詳細な仕様を考え、設計し、クライアントやPMとコミュニケーションを取りながらプロダクトを形にしていきます。

この教材は、そうした現場のプロセスを体験することを目的としています。

**【この教材の設定】**

あなたは開発会社のエンジニアです。クライアント企業のPM（プロジェクトマネージャー）から、書籍レビューアプリの開発を依頼されました。PMからは大まかな要件と画面デザイン（Bladeテンプレート）が提供されていますが、詳細な仕様は固まっていません。

コーチ = クライアントPM として、あなたはPMに対してヒアリングを行い、詳細な仕様を詰めていく必要があります。

**【この教材の進め方】**

1.  **要件の把握**: 本書に書かれている大まかな機能要件、URI、UI（Bladeテンプレート）を把握します。
2.  **思考と設計**: 「この機能を実現するには、どんなデータが必要か？」「どんなバリデーションが必要か？」「成功時/失敗時の画面遷移はどうすべきか？」といった詳細な仕様（基本設計）を自分自身で考え、言語化してください。
3.  **PMへのヒアリング**: 自分で考えた設計案をPM（コーチ）に提示し、「この仕様で問題ないか？」「他に考慮すべき点はあるか？」といった確認を行います。不明点があれば積極的に質問してください。
4.  **設計の確定**: PMからのフィードバックを元に設計をブラッシュアップし、最終的な仕様を確定させます。
5.  **実装**: 確定した設計を元に、実装に着手します。

本書には、あえて「正解」となる詳細な仕様は書かれていません。要件の行間を読み、自ら思考し、PMとコミュニケーションを取って仕様を詰めていくプロセスそのものが、この教材の最も重要な学習要素です。

### 1.2. ヒアリングのポイント

PMへのヒアリングでは、以下のような観点で質問・確認を行うと効果的です。

-   **画面遷移**: 「登録成功後はどの画面に遷移しますか？」「エラー時はどうなりますか？」
-   **バリデーション**: 「タイトルの最大文字数は何文字ですか？」「ISBNの形式チェックは必要ですか？」
-   **エラーメッセージ**: 「バリデーションエラー時のメッセージはどのような文言にしますか？」
-   **フラッシュメッセージ**: 「登録成功時に表示するメッセージは何ですか？」
-   **権限・認可**: 「他人の書籍を編集しようとした場合、どのような挙動にしますか？」
-   **エッジケース**: 「紐付く書籍があるジャンルを削除しようとした場合はどうしますか？」

### 1.3. 前提条件

- 基本機能編のすべての要件を満たしていること。
- 開発言語・フレームワークは PHP / Laravel (Laravel 10.x) を使用する。
- フロントエンドのBladeテンプレートは提供されたものを利用する。

## 2. 環境構築手順

### 2.1. Laravelプロジェクトの作成 (Laravel 10.x)

以下のDockerコマンドを実行して、Laravel 10.xを明示的に指定してプロジェクトを作成します。

```bash
docker run --rm \
    -u "$(id -u):$(id -g)" \
    -v "$(pwd):/var/www/html" \
    -w /var/www/html \
    -e COMPOSER_CACHE_DIR=/tmp/composer_cache \
    laravelsail/php82-composer:latest \
    composer create-project laravel/laravel:^10.0 book-review-app
```

### 2.2. Laravel Sailのインストール

プロジェクト作成後、`book-review-app` ディレクトリに移動し、Laravel Sailをインストールします。

```bash
# プロジェクトディレクトリに移動
cd book-review-app

# Laravel Sailをインストール
docker run --rm \
    -u "$(id -u):$(id -g)" \
    -v "$(pwd):/var/www/html" \
    -w /var/www/html \
    -e COMPOSER_CACHE_DIR=/tmp/composer_cache \
    laravelsail/php82-composer:latest \
    composer require laravel/sail --dev

# Sailの設定ファイルをパブリッシュ（MySQLを選択）
docker run --rm \
    -u "$(id -u):$(id -g)" \
    -v "$(pwd):/var/www/html" \
    -w /var/www/html \
    -e COMPOSER_CACHE_DIR=/tmp/composer_cache \
    laravelsail/php82-composer:latest \
    php artisan sail:install --with=mysql
```

### 2.3. フロントエンドのセットアップ (Vite & Tailwind CSS)

1.  **NPM依存パッケージのインストール**
    ```bash
    sail npm install
    ```

2.  **Tailwind CSSのインストール**
    ```bash
    sail npm install -D tailwindcss@^3.4.0 postcss autoprefixer
    ```

3.  **設定ファイルの生成**
    ```bash
    sail npx tailwindcss init -p
    ```

4.  **Tailwind CSSのテンプレートパス設定**
    `tailwind.config.js` を開き、`content`プロパティを以下のように設定します。
    ```javascript
    /** @type {import('tailwindcss').Config} */
    export default {
      content: [
        "./resources/**/*.blade.php",
        "./resources/**/*.js",
        "./resources/**/*.vue",
      ],
      theme: {
        extend: {},
      },
      plugins: [],
    }
    ```

5.  **CSSファイルにTailwindディレクティブを追加**
    `resources/css/app.css` の中身を以下の3行に置き換えます。
    ```css
    @tailwind base;
    @tailwind components;
    @tailwind utilities;
    ```

6.  **Vite開発サーバーの起動**
    新しいターミナルを開いて実行します。このコマンドは開発中、常に実行したままにしてください。
    ```bash
    sail npm run dev
    ```

### 2.4. .env ファイルとphpMyAdminの設定

1.  **.env ファイルの確認**
    `.env` ファイルを開き、データベース接続情報が以下と一致していることを確認し、**Google Books APIキー**を追加します。
    ```ini
    DB_CONNECTION=mysql
    DB_HOST=mysql
    DB_PORT=3306
    DB_DATABASE=laravel
    DB_USERNAME=sail
    DB_PASSWORD=password

    # Google Books APIキー（自身のキーに置き換える）
    GOOGLE_BOOKS_API_KEY=Your-API-Key
    ```

2.  **phpMyAdminの追加**
    `compose.yaml` を開き、`mysql` サービスの後に以下の設定を追加します。
    ```yaml
        phpmyadmin:
            image: 'phpmyadmin:latest'
            ports:
                - '${FORWARD_PHPMYADMIN_PORT:-8080}:80'
            environment:
                PMA_HOST: mysql
                PMA_USER: '${DB_USERNAME}'
                PMA_PASSWORD: '${DB_PASSWORD}'
            networks:
                - sail
            depends_on:
                - mysql
    ```

### 2.5. Sailの起動とエイリアス設定

1.  **Sailの起動**
    ```bash
    ./vendor/bin/sail up -d
    ```

2.  **エイリアス設定**
    ```bash
    echo "alias sail='[ -f sail ] && bash sail || bash vendor/bin/sail'" >> ~/.zshrc
    # または bash の場合
    # echo "alias sail='[ -f sail ] && bash sail || bash vendor/bin/sail'" >> ~/.bashrc
    
    # シェルを再起動
    exec $SHELL
    ```

3.  **アプリケーションキーの生成**
    ```bash
    sail artisan key:generate
    ```

## 3. 機能要件（追加・変更分）

| 大機能 | 中機能 | 機能概要 |
|---|---|---|
| **書籍管理** | **高度な検索機能** | 書籍一覧ページで、キーワード、ジャンル、並び順を組み合わせて書籍を検索できる。 |
| | **CSVエクスポート** | 検索結果を書籍一覧ページからCSV形式でダウンロードできる。 |
| | **ISBN書籍検索** | 書籍登録ページで、ISBNを入力してGoogle Books APIから書籍情報を自動取得・入力できる。 |
| **マイ読書レポート** | **統計表示** | ログインユーザーの読書活動に関する様々な統計情報（総読了冊数、継続日数、月別統計など）を表示する。 |
| **公開API** | **書籍情報提供** | 外部アプリケーション向けに、書籍の一覧と詳細情報をJSON形式で提供する認証不要のAPI。 |

---

### 3.1. 高度な検索機能 - 概要

- **目的**: ユーザーが目的の書籍を効率的に見つけられるようにする。
- **インターフェース**: 書籍一覧ページに検索フォームを設置。
- **検索条件**: キーワード（タイトル・著者）、ジャンル、並び順（新着、評価順など）をサポートする。

### 3.2. CSVエクスポート機能 - 概要

- **目的**: 書籍データをオフラインで利用できるようにする。
- **動作**: 検索結果をCSVファイルとしてダウンロードする。
- **ファイル形式**: UTF-8 (BOM付き)、ヘッダー行を含む。

### 3.3. ISBN書籍検索機能 - 概要

- **目的**: 書籍登録の手間を削減する。
- **動作**: ISBN-13をキーにGoogle Books APIを呼び出し、取得した書籍情報（タイトル、著者など）をフォームに自動入力する。
- **インターフェース**: 書籍登録・編集ページにISBN入力欄と検索ボタンを設置。

### 3.4. マイ読書レポート機能 - 概要

- **目的**: ユーザーの読書活動を可視化し、モチベーションを向上させる。
- **表示項目**: 総読了冊数、レビュー投稿日数、読書継続日数（現在/最長）、月別統計グラフなど。
- **実装方針**: LaravelのCollectionメソッドを積極的に活用し、宣言的なコードで統計処理を実装する。

### 3.5. 公開API機能 - 概要

- **目的**: 外部サービスとの連携を可能にする。
- **エンドポイント**: 書籍一覧取得API (`/api/v1/books`) と書籍詳細取得API (`/api/v1/books/{book}`) を提供する。
- **フォーマット**: JSON形式。一覧APIではページネーション情報を含める。

## 4. 非機能要件（概要）

| 項目 | 要件概要 |
|---|---|
| **コーディングスタイル** | - **型宣言の徹底**: すべてのコントローラ、モデル、FormRequest、Policyのメソッドに、引数と戻り値の型を明示的に宣言する。（例: `public function index(): View`）<br>- **リレーション戻り値型**: モデルのリレーションメソッドには、`HasMany`, `BelongsTo` などの具体的な戻り値型を宣言する。<br>- **PHPDoc**: 主要なメソッドには、処理内容、引数、戻り値を説明するPHPDocコメントを記述する。 |
| **Collectionメソッド** | - **宣言的なコード**: `foreach` などの手続き的なループを避け、`map`, `filter`, `reduce`, `groupBy` などのCollectionメソッドを積極的に活用し、宣言的で可読性の高いコードを記述する。特にマイ読書レポート機能でこれを徹底する。 |
| **外部連携** | - **HTTPクライアント**: 外部APIとの通信には、Laravel標準のHTTPクライアント (`Illuminate\Support\Facades\Http`) を使用する。 |
| **ファイルダウンロード** | - **ストリーミング**: CSVエクスポートなどの大容量ファイルを扱う可能性がある機能では、メモリ消費を抑えるため `StreamedResponse` を使用してレスポンスをストリーミングする。 |

## 5. 基本設計（概要）

### 5.1. ルーティング設計

- **Web**: 高度な検索、CSVエクスポート、ISBN検索、読書レポートのルートを`routes/web.php`に追加する。
- **API**: 書籍一覧・詳細APIのルートを`routes/api.php`に新規作成する。

### 5.2. コントローラ設計（概要）

| コントローラ | 主な責務 |
|---|---|
| **BookController** | 高度な検索ロジック、CSVエクスポート処理、ISBN検索処理を担当。 |
| **ReportController** | Collectionメソッドを駆使して各種読書統計を算出し、ビューに渡す処理を担当。 |
| **Api\V1\BookController** | APIリクエストを処理し、Eloquent APIリソースを使用してJSONレスポンスを生成する処理を担当。 |

### 5.3. テスト要件（概要）

- **対象**: 今回追加するすべての機能（検索、CSV、ISBN、レポート、API）をテスト対象とする。
- **カバレッジ**: コードカバレッジ80%以上を目標とする。
- **外部APIテスト**: `Http::fake()` を使用して外部APIをモック化し、安定したテストを実行する。
