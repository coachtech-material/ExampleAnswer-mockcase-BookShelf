## TSV のフォーマット

```
大項目 \t 中項目 \t 小項目 \t 修正前 \t 修正後 \t 対応要否 \t コメント \t 修正内容
```

- セル内改行は `\n` (literal 2 文字) でエスケープ
- バックスラッシュはそのまま（PHP namespace `Illuminate\Database\Migrations\Migration` 等が壊れないため）
- 行番号は **原本スプシの行番号と完全に一致** している（Basic Row 4 = スプシ Row 4 = Claude が "R4" と呼ぶもの）

## 各列の役割

| 列 | 名前 | 内容 |
|---|---|---|
| 1 | 大項目 | 例: 基本機能編_完全手順書、Chapter 02 等 |
| 2 | 中項目 | 例: Part 1: 要件定義書 |
| 3 | 小項目 | 例: 1. システム概要:技術スタック |
| 4 | 修正前 | 採点team から提示された修正前の表記 |
| 5 | 修正後 | 採点team から提示された修正後の表記 |
| 6 | **対応要否** | Claude が作業中に更新する欄。値: `完了` / `要判断` / `対応不要` / 空（未対応） |
| 7 | コメント（あれば） | 採点team からの補足 |
| 8 | **修正内容** | Claude が対応した内容の要約（commit SHA を含めることもある）を記載 |

## 運用フロー

1. Claude が Phase 1A / 2A 中に、対応した行に対して **col 6 を `完了`** に更新し **col 8 に修正内容** を記入
2. commit のメッセージにも R 番号を列挙（例: `fix(advanced): Phase 1A - R3,R4,R7-R17 反映`）
3. Phase 完了時、ユーザーが col 6 と col 8 を原本スプシにコピペで一括反映

## 採点者コメント表現の凡例

| 採点者の表現 | Claude のデフォルト判定 |
|---|---|
| 「修正をお願いします」「追加をお願いします」 | 🔴 反映必須（対応要否 = 完了） |
| 「不要ならスルーで」「対応不要でも大丈夫」「問題なければスルーで」 | 🟢 デフォルトスキップ（対応要否 = 対応不要） |
| 「武市さんへ：あっていますか？」等の内部議論 | 🟡 ユーザー判断仰ぐ（対応要否 = 要判断） |

🟡 要判断項目は umbrella Issue #57 のコメントとして集約する。

## 原本スプシへの同期

Claude は直接スプシのセルを書き換えできない。
そのため Phase 完了時に col 6（対応要否）と col 8（修正内容）の 2 列を、ユーザーが Sheets で範囲選択 → コピペで原本へ反映する。

- スプシ側に「修正内容」列がまだなければ、col 7 の右隣に追加してからペースト
- `\n` リテラルが含まれる場合は Sheets の `=SUBSTITUTE(A1, "\n", CHAR(10))` で改行に戻すか、そのまま貼って手動修正
