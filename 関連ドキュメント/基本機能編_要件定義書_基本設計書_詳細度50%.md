# 書籍レビューアプリ 要件定義書・基本設計書（基本機能編）- 生徒用

## 1. はじめに

### 1.1. 本書の目的と進め方

本書は、書籍レビューアプリケーションの「基本機能編」開発における**初期要件**を定義するものです。実際の開発現場では、最初から完璧な仕様書が渡されることは稀です。多くの場合、大まかな要件を元に、開発者は**自ら詳細な仕様を考え、設計し、時には関係者とコミュニケーションを取りながら**プロダクトを形にしていきます。

この教材は、そうした現場のプロセスを体験することを目的としています。

> **【この教材の進め方】**
> 1.  **要件の把握**: 本書に書かれている大まかな機能要件、URI、UI（Bladeテンプレート）を把握します。
> 2.  **思考と設計**: 「この機能を実現するには、どんなデータが必要か？」「どんなバリデーションが必要か？」「成功時/失敗時の画面遷移はどうすべきか？」といった**詳細な仕様（基本設計）を自分自身で考え、言語化**してください。
> 3.  **コーチへの相談**: 自分で考えた設計について、コーチに壁打ちをしたり、不明点をヒアリングしたりして、設計をブラッシュアップします。
> 4.  **実装**: 固まった設計を元に、実装に着手します。

本書には、あえて「正解」となる詳細な仕様は書かれていません。**行間を読み、思考し、コミュニケーションを取る**プロセスそのものが、この教材の最も重要な学習要素です。

### 1.2. 前提条件

- 開発言語・フレームワークは PHP / Laravel (Laravel 10.x) を使用する。
- フロントエンドのBladeテンプレートは `coachtech-material/Preparedblade-mockcase-BookShelf` リポジトリの `basic` ブランチで提供される。
- データベースは MySQL を使用する。
- 開発環境は Docker および Laravel Sail を使用する。

## 3. 機能要件

### 3.1. 機能一覧

| 大機能 | 中機能 | 機能概要 |
|---|---|---|
| **認証** | 会員登録 | メールアドレス、パスワード、名前でユーザー登録できる。 |
| | ログイン | メールアドレスとパスワードでログインできる。 |
| | ログアウト | ログイン状態からログアウトできる。 |
| **書籍管理** | 書籍一覧表示 | 登録されている書籍を10件ずつのページネーションで一覧表示する。 |
| | 書籍詳細表示 | 特定の書籍の詳細情報と、その書籍に紐付くレビューの一覧を表示する。 |
| | 書籍登録 | 書籍のタイトル、著者、ISBN、出版日、概要、画像URL、ジャンルを登録できる。 |
| | 書籍編集 | 自分が登録した書籍の情報を編集できる。 |
| | 書籍削除 | 自分が登録した書籍を削除できる。 |
| **レビュー管理** | レビュー投稿 | 書籍詳細ページから、5段階評価とコメントでレビューを投稿できる。 |
| | レビュー編集 | 自分が投稿したレビューを編集できる。 |
| | レビュー削除 | 自分が投稿したレビューを削除できる。 |
| **お気に入り機能** | お気に入り登録/解除 | 書籍をお気に入りに登録、またはお気に入りから解除できる。 |
| | お気に入り一覧 | 自分がお気に入りに登録した書籍を一覧表示できる。 |
| **いいね機能** | いいね登録/解除 | 他のユーザーのレビューに「いいね」を登録、または解除できる。 |
| **ジャンル管理** | ジャンル一覧表示 | 登録されているジャンルを、紐付く書籍数と共に一覧表示する。 |
| | ジャンル別書籍一覧 | 特定のジャンルに紐付く書籍を一覧表示する。 |
| | ジャンル登録 | 新しいジャンル名を登録できる。 |
| | ジャンル編集 | 既存のジャンル名を編集できる。 |
| | ジャンル削除 | 紐付く書籍がない場合に限り、ジャンルを削除できる。 |
| **ランキング機能** | ランキング表示 | レビューの平均評価が高い順に書籍トップ10をランキング形式で表示する。 |

### 3.2. 設計のヒント：バリデーションと認可

安全なアプリケーションを作るためには、**バリデーション（入力値検証）**と**認可（権限管理）**が不可欠です。以下の機能については、これらの実装が必要になることを念頭に置いて設計を進めてください。

- **バリデーションが必要な機能**:
  - 会員登録
  - ログイン
  - 書籍登録、編集
  - レビュー投稿、編集
  - ジャンル登録、編集

- **認可（ポリシー）が必要な機能**:
  - 書籍編集、削除（自分の書籍か？）
  - レビュー編集、削除（自分のレビューか？）

## 4. URI設計

| HTTPメソッド | URI | アクション | ルート名 |
|---|---|---|---|
| GET | `/` | 書籍一覧表示 | `books.index` |
| GET | `/books/create` | 書籍登録フォーム表示 | `books.create` |
| POST | `/books` | 書籍登録処理 | `books.store` |
| GET | `/books/{book}` | 書籍詳細表示 | `books.show` |
| GET | `/books/{book}/edit` | 書籍編集フォーム表示 | `books.edit` |
| PUT/PATCH | `/books/{book}` | 書籍更新処理 | `books.update` |
| DELETE | `/books/{book}` | 書籍削除処理 | `books.destroy` |
| POST | `/books/{book}/reviews` | レビュー投稿処理 | `reviews.store` |
| GET | `/reviews/{review}/edit` | レビュー編集フォーム表示 | `reviews.edit` |
| PUT/PATCH | `/reviews/{review}` | レビュー更新処理 | `reviews.update` |
| DELETE | `/reviews/{review}` | レビュー削除処理 | `reviews.destroy` |
| ... | ... | ... | ... |

（※ 認証、お気に入り、いいね、ジャンル、ランキングなど、他の機能のURIも同様に設計してください）
